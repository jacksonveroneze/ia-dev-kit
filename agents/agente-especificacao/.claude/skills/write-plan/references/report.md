# Relatório: write-plan

Formato fixo. O rascunho (template) vem primeiro; depois:

```
Completude:
| Item | Estado |
|---|---|
| Abordagem | presente ou a definir |
| Decisões técnicas | N, todas com origem: sim ou não |
| Componentes e arquivos | N, todos com caminho confirmado ou criar: sim ou não |
| Contrato | ... |
| Testes | cobertura dos CA: N de M |
| Comandos | presentes ou a definir |
| Rollout e rollback | presentes ou a definir |

Pendências: <N a definir, M (proposto, confirmar), K voltas à spec>
Perguntas:
1. <pergunta> (afeta <DT, componente ou teste>)
Mudanças: <o que mudou e por quê | rascunho inicial>
Instruções encontradas na entrada: <trecho citado | nenhuma>
```

## Ao parar
Spec ou resumo do código ausente, ou spec com pendência: uma linha com o que faltou; nada foi escrito.
